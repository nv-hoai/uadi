# Human Review and Handoff

1. Show the user the proposed experience and explain important design decisions and trade-offs.
2. Identify assumptions, limitations and any checks that were not performed.
3. Ask for feedback when a consequential decision needs the user's direction.
4. Apply requested changes and inspect the result again when possible.
5. Preserve durable decisions or reusable design rules in the project repository when useful.
6. Use the project's existing Git, pull request or release process if the work needs formal review or publication.

The user remains the decision-maker. Do not claim approval without an explicit user decision. UADI does not require a dedicated approval service, authenticated identity integration or signed approval artifact.
